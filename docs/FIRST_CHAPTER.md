# First Chapter: from a physical hello to time together

Two iPhones discover each other, detect a gentle shared bump, and exchange a short-lived invitation. The recipient previews common ground and an activity; the host confirms the person who arrived. A server-timed First 20 starts, followed by two independent completion confirmations. Confirmed minutes fill the friendship ring, and a memory appears on the friend profile. A suitable recurring crew gives the pair a concrete next meeting to explore.

## What's implemented

- Local Expo module `apps/mobile/modules/friend-bump`: foreground MultipeerConnectivity discovery, required transport encryption, ephemeral peer IDs, a matching pair symbol on both screens, and Core Motion detection on both phones.
- Discovery stops if multiple participating peers are visible. Motion events must arrive in a short shared window; both devices acknowledge before the host invitation is transmitted. This is a prototype heuristic, **not UWB ranging or verified physical proximity**.
- Both users explicitly consent before the friendship connection and timer begin. Nearby discovery itself sends no names or profiles.
- Reusable NFC cards/stickers and typed codes use the same preview and consent flow. This is separate from the iPhone bump transport.
- Animated friendship rings, shared orbit, staggered common-ground reveal, native haptic feedback, and reduced-motion support.
- A single-use, 10-minute invitation, idempotent claim/start/confirmation, participant-only hangout access, expiry/cancellation, and a Home card to resume.
- The server enforces 20 elapsed minutes and two confirmations before crediting exactly 20 minutes. Confirm within 24 hours of starting. This is self-attested time, not location-verified attendance.
- Conversation ideas use Meta Model API when configured. Matching uses only actual shared interest tags. The model phrases an activity; it does not invent matching facts. AI failures use labeled templates. Both phones receive the saved activity.
- A next-crew suggestion uses shared interests, the same city, overlapping availability, and at least two available places. Each person separately chooses whether to join. A suggestion does not reserve capacity.

## Run the app

From the repository root:

```sh
npm ci
npm run db:push -w @200h/api
npm run db:seed -w @200h/api  # resets demo data; omit if preserving an existing database
npm run api
```

Start Expo in a second terminal:

```sh
npm run mobile
```

Use one shared API reachable from both phones. Set `EXPO_PUBLIC_API_URL` in `apps/mobile/.env` to the laptop's LAN address (for example `http://192.168.1.20:8787`), or use a hosted API. The nearby handshake is local, but previews and saved friendship data require the API.

For Meta AI, copy `apps/api/.env.example` to `.env` and set `MODEL_API_KEY`. The default is `https://api.meta.ai/v1`, model `muse-spark-1.3`. Legacy `MUSE_API_KEY` and compatible-provider overrides still work. No model key is bundled into the app. See [Meta Chat Completions docs](https://dev.meta.ai/docs/protocols/chat-completions).

## Install on two iPhones

The custom module needs a native build; Expo Go and a simulator cannot test the bump. With full Xcode installed and the phones configured for development:

```sh
cd apps/mobile
npx expo run:ios --device
```

Install on each phone, sign in as **different users** (development onboarding offers Alex and Sam), and allow Local Network and motion access. Keep Wi-Fi and Bluetooth on and both connection screens in the foreground. The generated app Info.plist includes the Bonjour service and permission descriptions. Native project directories are generated by Expo; do not edit them manually.

The native module intentionally does not use Nearby Interaction/UWB, so it does not require UWB-capable iPhone models. Its single-peer assumption and motion threshold need measurement on the actual demo devices. Validate pairing time, missed bumps, simultaneous unrelated motion, app backgrounding, denied permissions, and discovery with a third participant before relying on it on stage.

## A short, honest demo

1. Alex and Sam open **Tap to connect** and press **Ready to bump**.
2. Wait for matching pair symbols, then gently bump together.
3. Show Sam's preview, shared interests, and conversation activity.
4. Sam chooses to begin. Alex confirms Sam, and both see their shared orbit and timer.
5. Show the suggested recurring crew and choose to explore it. No waiting 20 minutes is required to demonstrate the core value.
6. Open Nina's seeded friendship profile to show an already completed 20-minute memory. Explain that this is seeded history; there is no timer bypass in the app.

If the native handshake fails, demonstrate the same experience by sharing the 6-character invitation code. A code proves possession of an invitation, not physical proximity.

## Verification and remaining limitations

Run `npm run typecheck`, `npm run lint`, and `npm test`. Integration tests create an isolated temporary database from the real Drizzle schema. They cover consent, single-use codes, expiry, unauthorized access, resumability, concurrent claims, and exactly-once time credit.

JavaScript exports and Swift parsing do not confirm that the native module compiles, installs, or pairs reliably on devices. A full Xcode build and a measured two-iPhone run remain required. The repository's existing `x-user-id` demo authentication must be replaced before public use; participant checks currently depend on that identity stub.
